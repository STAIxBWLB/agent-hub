# Adapter conformance

`bun test test/conformance` runs actual adapter implementations against synthetic local transports. It requires no provider account and proves no live native client compatibility. The shared runner in `kit.ts` accepts an adapter fixture and checks delivery occupancy, a real transport round trip, safe recovery metadata and observed teardown. Native-specific assertions live beside it.

- Enrollment follows `ADAPTERS`, not a second registration loop. `enrollment.ts` checks every builtin and its separately named `:reviewer` variant, with concrete unsupported reasons rather than silent skips. Missing fixtures, stale enrollment, a removed agy reason and an unenrolled test kind fail the guard.
- Claude, Codex, Kimi, Pi, local, Qwen and Jcode run the shared contract. Driven peers are created through the selected definition's `start.create` and its exact daemon transport port. Claude's authenticated channel is the host-owned external-hello exception: the real daemon constructs it; the kit invents no headless factory.
- Every ACP definition participates. Kimi and Qwen use the generic ACP engine; Jcode uses its owned daemon plus ACP engine. Native permission/mode/quota legs without a verified protocol have explicit `UNSUPPORTED_LEGS` reasons, with actual Jcode unmanaged-mode refusal checked on the running factory-created peer. Kimi's native TUI is separately exercised as a pull-only external channel.
- ACP fixtures use the existing fake stdio agent; Jcode uses its fake private daemon plus ACP client, Codex uses its fake app-server and TUI proxy, Pi uses its fake RPC owner and authenticated extension bridge, local uses its fake HTTP gateway, Claude uses an authenticated channel against the real daemon.
- Kimi, Qwen, Jcode and Codex perform actual resume RPCs. Pi opens a persisted session and checks its exact identity. Local has no persisted conversation resume protocol. Claude reattaches a channel; its native transcript/session remains owned by the native client.
- Kimi, Qwen, Jcode and Pi assert owned-process disappearance on stop. The additional Codex launcher test checks both the launcher and native child disappear as a group. Local's model transport and Claude's native terminal are not daemon-owned child processes.
- Synchronous busy is mandatory for driven peers. Claude channel insertion deliberately stays idle: native hooks own its occupancy and turn completion. This is the existing native-hook contract, not an exemption introduced by the registry.
- Kimi and Qwen exercise permission approval, exact hub-tool autoapproval, lookalike refusal, mode change and a late acknowledgement after mode timeout. Local checks denied filesystem mutation and direct host hub-tool dispatch. Jcode verifies that unmanaged runtime mode changes are refused. Claude permissions are launch flags and Pi/local permissions are hub gates, so neither has an ACP mode-ack timeout to test.
- Kimi's verified pre-activity quota refusal produces `failed_safe` only after confirmed pause. Codex's accepted native quota failure remains `needs_review`; its definitive admission refusal produces `failed_safe`. No pinned quota classifier exists for Qwen or Jcode. Local has no native account quota; Pi/Claude report host/native-session quota through their respective integrations.
- Explicit watchdog expiry follows observed native acceptance or the consumed native prompt marker. Kimi and Qwen run the ACP generation fence; Jcode holds a real fake-owned prompt until the test releases it, waits for its late settlement, then checks only the successor answer publishes. Ordered transport barriers consume late ACP/Codex results before checking their generation fences. The local fake returns despite cancellation and the real parser consumes that response before the stale-answer assertion. Pi's authenticated bridge rejects stale generation completion and retains the current turn.

The broader existing native-hook, permission, Pi extension, crash/recovery and teardown regression suites remain required. This kit does not replace them or claim to simulate provider accounts.

Antigravity is the eighth optional builtin. Its actual pull-channel round trip and launcher/session/generation-fenced native hooks are covered by `test/agy-peer.test.ts`. `agy.test.ts` asserts the enrollment map's explicit reason for unsupported driven headless delivery, permission-acknowledgement, quota and resume legs; no `test.skip` hides that missing contract. They are not synthetic successes; agy P1 has no headless driver or budget source and its native permission policy stays unmanaged. The pinned native plugin/hook transport receipt is separate from these fixtures and from actual interactive TUI/IDE verification.

Fresh reviewer variants are separate enrollment identities. Their generic text-prompt legs remain explicitly unsupported: readiness requires the native isolation receipt, immutable review binding and task-MCP verdict authority exercised by `test/reviewer-print.test.ts`, `test/codex-review-isolation.test.ts` and `test/kimi-review*.test.ts`. The unavailable agy reviewer stays metadata-only. Coherence lint includes every variant and requires native-hook completion to have the Claude transport or a native facts hook.
