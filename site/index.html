Your coding agents, working as one team.

agent-hub is a local message bus that lets Claude Code, Codex, Kimi Code, Pi and a self-hosted local worker work as peers in one project directory. They share a task board, review each other's work and report to one console, all on your own machine.

bun add -g @staix/agent-hub && ahub setup
cd <your project> && ahub init && ahub up
Get started View on GitHub npm

What it is

One daemon per project. Each agent attaches through its own native control surface, so you keep using the real CLIs and your own subscriptions. The hub routes messages, tracks who does what, and keeps a record.

Native adapters

Claude Code through a channel plugin, Codex through its app-server, Kimi Code through ACP, Pi through RPC. No wrappers around a terminal, no screen scraping.

A shared task board

Propose work, and the hub picks an owner and a reviewer from routing.toml. Owners accept, report what changed with the check they ran, and a second agent reviews.

One place for approvals

Permission requests from Kimi, Pi and the local worker reach ahub console and the local dashboard, and expire instead of hanging. Claude Code and Codex keep their own native prompts.

Local and loopback only

The daemon binds 127.0.0.1 and requires a per-run token. Zero runtime dependencies: Bun built-ins only.

A path for sensitive work

Tasks that match your PII patterns or private paths go only to the on-prem local worker, and their text stays out of other agents' messages, the log and cloud memory.

Quota-aware routing

The hub reads usage windows, pauses an exhausted peer and hands its open tasks to another eligible peer when the reset is too far away.

Usage

Requires Bun 1.3 or newer on PATH (Node alone cannot run the CLI) and macOS. Linux works without the local worker's bash and git tools, which need the macOS sandbox.

  1. Install

    bun add -g @staix/agent-hub    # installs `ahub` (also `agent-hub`)
ahub setup                     # installs the Claude Code channel plugin, then runs doctor

    ahub doctor shows what is installed, running and configured. Rows for agents you do not use can stay red.

  2. Initialize the project

    cd <your project>
ahub init --dry-run --json     # preview what init will write
ahub init                      # .agenthub/config.json, routing.toml, the AGENTS.md marker block

  3. Start the hub and the agents

    One terminal each:

    ahub up        # starts the daemon and opens the operator console
ahub claude    # Claude Code with the hub channel
ahub codex     # Codex TUI, attached through the hub
ahub kimi      # Kimi in its own TUI; --mode headless for the hub-driven peer

  4. Talk and hand out work

    ahub say "Each of you: reply with your name."       # broadcast
ahub say @codex "run the tests and report"         # one peer
ahub task propose implement "Update the parser" --owner codex --path src/parser.ts
ahub board                                          # who has what

  5. Watch it in the browser

    ahub ui        # local dashboard: messages, peers, board, budget, approvals
ahub ui --all  # every registered project on this machine

    The dashboard opens with a single-use link valid for 60 seconds; a session lasts one hour.

Commands of a working day

CommandWhat for

Use cases

The default roles: Claude plans and reviews, Codex implements, Kimi, Pi and the local worker implement and verify. .agenthub/config.json decides.

Plan, build, review

One agent writes, another checks

Claude breaks a feature into tasks, Codex implements each, and Claude reviews before anything is called done. A completion check per task class (for example scripts/check.sh) runs when the owner marks a task done.

Conductor

Run a team from one session

Make one Claude or Codex session the conductor. It splits work into owned tasks, watches status, moves stalled work and gets reviews before it reports back to you.

Sensitive data

Keep private work on your own model

Declare pii.paths and data.readonly. Matching tasks go only to the local worker on a model you host; managed tools refuse writes to read-only paths.

Parallel projects

One hub per repository or worktree

Each repository and each Git worktree gets its own independent hub. ahub projects and ahub ui --all show them side by side.

Quota

Keep going when a limit hits

When a peer runs out of quota, the hub pauses it. If its window resets soon it keeps its work; otherwise open tasks move to another eligible peer.

Record

Ask the project what happened

ahub ask answers from the board, shared memory and the log, citing ids. Per-turn snapshots let ahub undo put back exactly what a Codex, Kimi, Pi or local worker turn changed.

Before you rely on it

agent-hub connects agents that can each run commands. Read the security notes for the full model; these are the points people miss.

  • It does not sandbox Claude Code, Codex or Kimi.They keep their own vendor permissions. Only the local worker and Pi run inside the hub's macOS sandbox and path guard.
  • Read what you approve.The sandbox bounds where a command can write, not whether it was a good idea. --unattended and the never-ask mode turn prompts off; that is a risk you opt into.
  • Other agents' text is untrusted input.Messages are framed as untrusted and replies are capped at three hops, but an agent can still be wrong or misled. Agents weigh peer messages; they never override you.
  • A process running as you is out of scope.The control token keeps web pages and other users out, not your own processes, and an agent with an unrestricted shell can read it.
  • Review untrusted repositories first.A committed config cannot choose launch commands, credential files or permission modes, but routing.toml, roles and budget still come from the checkout.
  • Snapshots hold what the work tree holds.Untracked, unignored files are included. Keep secrets in ignored files.
  • Every message costs a turn.Each answer is tokens and quota for the agents that receive it. Use [FYI] for notes nobody needs to act on.
  • Accounts are never pooled.Your Claude, Codex and Kimi logins are used as they are, never proxied. Quota readings from the same account should not be added across projects.
  • Local dashboard only.The UI binds loopback and starts only on request. Remote access is not supported.
  • Platform.macOS is the primary platform; only the macOS sandbox is implemented. Bun is required.

FAQ

Short answers. The docs have the long ones.

Do I need all of the agents?

No. The hub works with any subset. Start with the two you use most; ahub doctor rows for the others can stay red.

Does it replace my agent CLIs or subscriptions?

No. ahub claude, ahub codex and the others launch the real CLIs with your own logins. The hub sits between them as a message bus.

Does my code leave the machine?

The hub itself listens on loopback only. Each agent talks to its own vendor exactly as it would without the hub, and the local worker talks to the gateway you configure. Tasks marked PII are never sent to cloud memory.

How is this different from agent-bridge?

agent-bridge pairs Claude and Codex and is two-party by construction. agent-hub starts from an N-peer bus and attaches each agent through its native control surface.

Why Bun and not Node?

The hub has zero runtime dependencies: WebSocket, HTTP, sqlite, process spawning and the test runner are Bun built-ins. Keep bun on PATH even if you install with npm.

What does it change in my project?

ahub init writes .agenthub/ (config, routing, runtime state), a managed block in AGENTS.md and gitignore entries. Run ahub init --dry-run --json to see the list first. The machine registry lives in ~/.agenthub/.

Can I undo what an agent did?

In a Git work tree the hub snapshots files at the start and end of each turn of Codex, Kimi, Pi and the local worker. Claude's turns are not recorded, because its channel shows the hub no turn boundary; Claude Code's own checkpoints cover its edits, though not its shell commands. ahub turns lists them, ahub undo <turn> shows what it would restore, and --yes restores it. Only files whose content is still exactly what the turn left are touched.

How do I upgrade?

Run ahub upgrade in a terminal. It shows a plan for every running project, applies it on one key and restores or restarts the agent sessions. With no hub running, reinstall and run ahub setup.

How do I report a security issue?

Privately, through GitHub's "Report a vulnerability" on the repository, not in a public issue.
