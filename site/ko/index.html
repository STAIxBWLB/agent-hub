코딩 에이전트들을 한 팀으로.

agent-hub는 Claude Code, Codex, Kimi Code, Pi, 그리고 직접 호스팅하는 로컬 워커가 한 프로젝트 디렉토리에서 동료로 일하게 하는 로컬 메시지 버스입니다. 작업 보드를 함께 쓰고, 서로의 작업을 리뷰하고, 하나의 콘솔로 보고합니다. 모두 내 컴퓨터 안에서 돌아갑니다.

bun add -g @staix/agent-hub && ahub setup
cd <프로젝트> && ahub init && ahub up
시작하기 GitHub에서 보기 npm

소개

프로젝트마다 데몬 하나. 각 에이전트는 자기 고유의 제어 인터페이스로 붙기 때문에, 원래 쓰던 CLI와 내 구독을 그대로 씁니다. 허브는 메시지를 라우팅하고, 누가 무엇을 맡았는지 추적하고, 기록을 남깁니다.

네이티브 어댑터

Claude Code는 채널 플러그인, Codex는 app-server, Kimi Code는 ACP, Pi는 RPC로 연결합니다. 터미널을 감싸거나 화면을 긁어오지 않습니다.

공유 작업 보드

작업을 올리면 허브가 routing.toml에 따라 담당자와 리뷰어를 정합니다. 담당자는 수락하고, 바뀐 내용과 돌린 검증을 보고하고, 다른 에이전트가 리뷰합니다.

승인은 한 곳에서

Kimi, Pi, 로컬 워커의 권한 요청이 ahub console과 로컬 대시보드로 모이고, 응답이 없으면 멈춰 있지 않고 만료됩니다. Claude Code와 Codex는 각자의 기본 확인 창을 그대로 씁니다.

로컬, loopback 전용

데몬은 127.0.0.1에만 바인딩하고 실행마다 발급되는 토큰을 요구합니다. 런타임 의존성 0개, Bun 내장 기능만 씁니다.

민감한 작업의 별도 경로

PII 패턴이나 비공개 경로에 걸리는 작업은 온프레미스 로컬 워커에만 가고, 그 내용은 다른 에이전트의 메시지, 로그, 클라우드 메모리에 남지 않습니다.

쿼터를 아는 라우팅

사용량 윈도우를 읽어 소진된 에이전트를 일시정지하고, 리셋까지 너무 멀면 열린 작업을 다른 에이전트에 넘깁니다.

에이전트별 연결 방식

에이전트수신송신
Claude Codeahub claude로 띄우면 채널 플러그인 push, 아니면 hub_inboxMCP 도구
Codexapp-server turn/start(유휴), turn/steer(작업 중)프록시가 에이전트 메시지를 읽음
Kimi CodeACP session/promptACP session/update 스트림
PiRPC 또는 관리형 TUI 확장허브가 승인한 도구
로컬 워커직접 호스팅하는 모델(OpenAI 호환 게이트웨이) 위에서 도는 허브 네이티브 에이전트 루프, macOS 샌드박스 적용

Qwen Code와 Jcode는 선택 사항입니다. 모든 에이전트를 설치할 필요는 없고, 일부만으로도 동작합니다.

사용법

Bun 1.3 이상이 PATH에 있어야 하고(Node만으로는 CLI가 돌지 않음) macOS가 기본입니다. Linux에서도 동작하지만 로컬 워커의 bash·git 도구는 macOS 샌드박스가 필요해 빠집니다.

  1. 설치

    bun add -g @staix/agent-hub    # `ahub`(별칭 `agent-hub`) 설치
ahub setup                     # Claude Code 채널 플러그인 설치 후 doctor 실행

    ahub doctor가 설치·실행·설정 상태를 보여줍니다. 쓰지 않는 에이전트 행은 빨간색이어도 괜찮습니다.

  2. 프로젝트 초기화

    cd <프로젝트>
ahub init --dry-run --json     # init이 쓸 내용을 미리 보기
ahub init                      # .agenthub/config.json, routing.toml, AGENTS.md 마커 블록

  3. 허브와 에이전트 띄우기

    터미널 하나씩:

    ahub up        # 데몬 시작 + 운영 콘솔 열기
ahub claude    # 허브 채널이 붙은 Claude Code
ahub codex     # 허브를 거쳐 붙은 Codex TUI
ahub kimi      # Kimi 자체 TUI, 허브가 구동하는 모드는 --mode headless

  4. 말 걸고 일 나누기

    ahub say "Each of you: reply with your name."       # 전체 방송
ahub say @codex "run the tests and report"         # 한 에이전트에게
ahub task propose implement "Update the parser" --owner codex --path src/parser.ts
ahub board                                          # 누가 무엇을 맡았나

  5. 브라우저로 보기

    ahub ui        # 로컬 대시보드: 메시지, 에이전트, 보드, 예산, 승인
ahub ui --all  # 이 컴퓨터에 등록된 모든 프로젝트

    대시보드는 60초 안에 열어야 하는 1회용 링크로 열리고, 세션은 1시간 유지됩니다.

매일 쓰는 명령

명령용도
ahub say [@peer] <text>대화. 기록만 남길 메모는 [FYI]로 시작.
ahub task propose <title>보드에 작업 등록. 담당자·리뷰어·분류는 허브가 정함.
ahub board / ahub task show <id>전체 현황과 작업 하나의 상세.
ahub review <id> approved|changes_requested "<note>"콘솔에서 리뷰.
ahub status / ahub budget에이전트, 큐, 일시정지, 쿼터 윈도우.
ahub ask <question>보드·공유 메모리·로그에 근거한 답, 근거 id 포함.
ahub turns / ahub undo <turn>에이전트 턴마다 바뀐 파일과 그 복원.
ahub upgrade실행 중인 허브를 최신 릴리스로, 계획을 확인한 뒤 적용.
ahub stop <peer> / ahub killheadless 에이전트 하나 정지, 또는 데몬과 그가 띄운 모든 것 정지.

자세한 내용은 quickstart와 운영 가이드(영문)에 있습니다.

유즈케이스

기본 역할: Claude는 계획과 리뷰, Codex는 구현, Kimi·Pi·로컬 워커는 구현과 검증. 실제 역할은 .agenthub/config.json이 정합니다.

계획, 구현, 리뷰

한 에이전트가 쓰고, 다른 에이전트가 검토

Claude가 기능을 작업으로 쪼개고, Codex가 하나씩 구현하고, 완료 전에 Claude가 리뷰합니다. 작업 분류마다 완료 검증(예: scripts/check.sh)을 걸어두면 담당자가 완료를 보고할 때 자동으로 돌아갑니다.

컨덕터

세션 하나로 팀 운영

Claude나 Codex 세션 하나를 컨덕터로 지정합니다. 작업을 나눠 맡기고, 상태를 지켜보고, 멈춘 작업을 옮기고, 리뷰를 받은 뒤에 결과를 보고합니다.

민감 데이터

비공개 작업은 내 모델로

pii.paths와 data.readonly를 선언하면, 해당 작업은 직접 호스팅하는 로컬 워커에만 가고 관리형 도구는 읽기 전용 경로에 쓰기를 거부합니다.

병렬 프로젝트

저장소·worktree마다 독립 허브

저장소마다, Git worktree마다 독립된 허브가 뜹니다. ahub projects와 ahub ui --all로 한눈에 봅니다.

쿼터

한도에 걸려도 계속 진행

에이전트의 쿼터가 바닥나면 허브가 일시정지합니다. 리셋이 가까우면 작업을 그대로 두고, 멀면 열린 작업을 다른 에이전트에 넘깁니다.

기록

무슨 일이 있었는지 프로젝트에 묻기

ahub ask는 보드·공유 메모리·로그를 근거로 id를 인용해 답합니다. 턴마다 스냅샷이 남아 ahub undo로 그 턴이 바꾼 것만 되돌릴 수 있습니다.

유의점

agent-hub는 각자 명령을 실행할 수 있는 에이전트들을 연결합니다. 전체 모델은 보안 노트(영문)에 있고, 아래는 놓치기 쉬운 점입니다.

  • Claude Code, Codex, Kimi를 샌드박스에 넣지 않습니다.각 벤더의 권한 체계를 그대로 씁니다. 허브의 macOS 샌드박스와 경로 가드는 로컬 워커와 Pi에만 적용됩니다.
  • 승인하기 전에 읽으세요.샌드박스는 명령이 어디에 쓸 수 있는지를 제한할 뿐, 그 명령이 옳은지는 판단하지 않습니다. --unattended와 never-ask 모드는 확인을 끄는 것이고, 그 위험은 직접 선택하는 것입니다.
  • 다른 에이전트의 메시지는 신뢰할 수 없는 입력입니다.메시지는 untrusted로 표시되고 답장은 3홉으로 제한되지만, 에이전트가 틀리거나 오도될 수는 있습니다. 동료 메시지는 참고할 뿐, 사용자 지시를 넘어서지 않습니다.
  • 내 계정으로 도는 프로세스는 막지 않습니다.제어 토큰은 웹 페이지와 다른 사용자를 막을 뿐이고, 제한 없는 셸을 가진 에이전트는 토큰을 읽을 수 있습니다.
  • 신뢰할 수 없는 저장소는 먼저 검토하세요.커밋된 설정은 실행 명령, 자격 증명 파일, 권한 모드를 고를 수 없지만, routing.toml, 역할, 예산 설정은 체크아웃에서 그대로 옵니다.
  • 스냅샷은 작업 트리 내용을 그대로 담습니다.추적되지 않고 ignore되지 않은 파일도 포함됩니다. 비밀 값은 ignore된 파일에 두세요.
  • 메시지 하나가 턴 하나입니다.답장 하나하나가 받는 에이전트의 토큰과 쿼터를 씁니다. 아무도 반응할 필요 없는 메모는 [FYI]로.
  • 계정은 공유·풀링하지 않습니다.Claude, Codex, Kimi 로그인은 그대로 쓰이고 프록시되지 않습니다. 같은 계정의 쿼터 수치를 프로젝트끼리 더하면 안 됩니다.
  • 대시보드는 로컬 전용입니다.UI는 요청할 때만 loopback에 뜹니다. 원격 접속은 지원하지 않습니다.
  • 플랫폼.macOS가 기본 플랫폼이고 샌드박스도 macOS용만 구현돼 있습니다. Bun이 필요합니다.

FAQ

짧은 답입니다. 긴 답은 문서(영문)에 있습니다.

에이전트를 전부 설치해야 하나요?

아니요. 일부만으로도 동작합니다. 가장 많이 쓰는 두 개로 시작하세요. 나머지의 ahub doctor 행은 빨간색이어도 됩니다.

기존 에이전트 CLI나 구독을 대체하나요?

아니요. ahub claude, ahub codex 등은 원래 CLI를 내 로그인으로 띄웁니다. 허브는 그 사이의 메시지 버스입니다.

내 코드가 컴퓨터 밖으로 나가나요?

허브 자체는 loopback에서만 듣습니다. 각 에이전트는 허브가 없을 때와 똑같이 자기 벤더와 통신하고, 로컬 워커는 설정한 게이트웨이와 통신합니다. PII로 분류된 작업은 클라우드 메모리로 보내지 않습니다.

agent-bridge와 뭐가 다른가요?

agent-bridge는 Claude와 Codex 둘을 잇는 구조입니다. agent-hub는 N명이 참여하는 버스에서 출발해, 각 에이전트를 고유 제어 인터페이스로 붙입니다.

왜 Node가 아니라 Bun인가요?

런타임 의존성이 0개이기 때문입니다. WebSocket, HTTP, sqlite, 프로세스 실행, 테스트 러너가 모두 Bun 내장입니다. npm으로 설치하더라도 bun은 PATH에 있어야 합니다.

내 프로젝트에 무엇이 바뀌나요?

ahub init은 .agenthub/(설정, 라우팅, 런타임 상태), AGENTS.md의 관리 블록, gitignore 항목을 씁니다. ahub init --dry-run --json으로 먼저 목록을 볼 수 있습니다. 머신 레지스트리는 ~/.agenthub/에 있습니다.

에이전트가 한 일을 되돌릴 수 있나요?

Git 작업 트리에서는 턴 시작과 끝에 파일 스냅샷을 남깁니다. ahub turns로 목록을 보고, ahub undo <turn>로 복원 대상을 확인하고, --yes로 복원합니다. 그 턴이 남긴 내용과 정확히 같은 파일만 건드립니다.

업그레이드는 어떻게 하나요?

터미널에서 ahub upgrade를 실행합니다. 실행 중인 모든 프로젝트의 계획을 보여주고, 키 하나로 적용하고, 에이전트 세션을 복원하거나 재시작합니다. 실행 중인 허브가 없으면 다시 설치하고 ahub setup만 하면 됩니다.

보안 문제는 어떻게 제보하나요?

공개 이슈가 아니라 저장소의 GitHub "Report a vulnerability"로 비공개 제보해 주세요.
