## Corrected defects

- Person reservation protection: planner grooming could clear or replace a person's reserved peer, or write the same value to change its provenance and then bypass the pull guard. Shared provenance checks now refuse all planner reservation writes while the current reservation belongs to a person. Person overrides and ordinary planner reservations remain supported.
- Pi roster return: a native start or settlement arriving during a session snapshot request could be overwritten by its stale idle flag. This could admit work during a personal turn or leave queued work permanently busy. Authenticated lifecycle changes now invalidate the snapshot; the verified owner, detached state and queue remain intact for a fresh retry.
- Deferred memory indexing: goal and unscoped suggestion reads bypassed the freshness check used by note reads. After an append succeeded while SQLite was busy, these readers could retain stale goals, links, leases or suggestion verdicts. All three reader families now share the freshness check without changing log bytes or the index schema.
- Overdue board rendering: the cached board did not refresh when time alone crossed a task deadline. Its key now includes the derived overdue IDs, with the same values used for card badges. Unchanged overdue state preserves DOM identity.

## Verification

Before the source changes, 24 new assertions failed for the reported conditions and one new compatibility case passed. The same regressions were retained unchanged after the fixes. The related four-file suite then passed 94 tests and 542 assertions with no failures in 44.02 seconds.

The memory regressions use real SQLite write contention, both the writer and another pre-opened store, and compare the recovered index with a rebuild. Pi regressions interleave authenticated lifecycle events and snapshot acknowledgements, then verify a fresh retry and exactly-once queued delivery. The board regression executes the actual render cache with a controlled clock and checks DOM identity before and after the deadline.

Eight mutation guards exercise the new protections. Two existing mutation selectors were retargeted to the refactored code while preserving their original test and mutation intent. All 390 selectors match exactly once. Final full-gate and mutation-run outcomes are recorded on the PR at its exact reviewed head; selector matching alone is not a passing mutation run.

## Remaining limits

- Import identity needs a compatibility design: the same claude-mem observation can acquire different content IDs when filesystem-derived graph nodes differ across machines. A safe correction must retain old content-hash validation, append-only logs, graph determinism and existing forget/supersede references. This audit does not silently rewrite those logs.
- Import scan semantics need clarification: the current limit is applied before project filtering, so older rows from unrelated projects can consume the scan window. A project-aware bounded pagination design should preserve the existing result counters and privacy checks.
- Existing native/account, physical terminal/font and research-effect obligations remain unverified. Fixture or source success does not close those release obligations.
- This change does not publish a release, upgrade an installed CLI or restart a live daemon.


## Additional review: acknowledgment before native activity

The first corrective head passed the local full gate (2,667 tests, zero failures,
188,881 assertions, `check: OK`, no owned daemon leaks) and both platform checks.
External review then identified the opposite transport ordering: an idle snapshot
ACK can arrive before a personal start event, so a daemon-side event counter alone
cannot prevent native prompt insertion or erroneous personal-output attribution.
Those earlier passing checks therefore do not certify this additional race.

The follow-up extends the verified Pi bridge handshake with native prompt admission
and command lineage. Native prompt consumption, not receipt of an idle snapshot,
is the insertion boundary. A legacy extension without this proof cannot rejoin the
roster. Dedicated extension/adapter regressions cover the additional transport
ordering; final results belong to the PR's current head.


The extension performs its final idle/generation check and prompt insertion in
one synchronous JavaScript turn. The pinned native path claims an active run
before its first await; if the post-insertion idle check does not prove that
claim (for example, another extension defers it during settlement), the effect
is classified as uncertain and no hub lineage is lent to a later personal turn.
The callback barrier supports normal queue draining; it is not treated as an
atomic reservation across all third-party extension callbacks.

The dedicated follow-up regressions cover the actual extension, retained native
owner, delivery journal, malformed refusal fields, legacy capability refusal,
capability downgrade, accepted-turn replacement and old-lineage retirement.


The follow-up Pi suite passed 72 tests with 642 assertions and no failures in
9.53 seconds, followed by a successful TypeScript check. This includes 11 new
prompt-admission regressions and the existing Pi, roster, receipt and ceiling
suites. All existing assertions were retained; the shared fake bridge now sends
the additive capability and command lineage of the current extension.
