# 0.16.0 release verification

This record covers release preparation and source review. It claims no installation, running-hub restart or live TUI launch.

## Candidate

Version 0.16.0, built from merged main 0ba9bc09. The release commit 267f39c0 carries the version, CHANGELOG section and bundle, and every document stamp names it. The person directed the release on 2026-10-25. It includes features, so the minor version is bumped (AGENTS.md, Releasing step 1). It ships with agent-mem 0.7.0, which was published first through its tag workflow and read back from the registry (version, tarball and integrity; `latest` 0.7.0) and from its GitHub Release body.

- Always-ask slice 3 (#750): the local worker, Pi and Codex command approvals are classed. A throwing gate asks deny-only. `gh api graphql` is classed by operation (#761), and the literal words around a shell expansion are classed, failing closed where the opaque part can change the class (#763).
- Memory:
  - the hub uses the amem library for recall and capture, with no claude-mem worker calls (#752);
  - verified symbol anchors and `ahub doctor --stale-anchors` (#769);
  - bounded preparation that keeps historical recall (#770);
  - current-head code neighbours for graphs and briefs (#771);
  - the exact agent-mem pin is 0.7.0 (this release's pin PR), passing the hub's own command names.
- Planner authority: task and release planner bindings are persisted, with up to 8 planners and the `task_planners` floor (#755). Backlog phase dependencies and issue planning (#766). The board-changed notice skips its author, coalesces per planner and is fyi weight when no plan review is needed (#767).
- Deliverables: `ahub deliverables` and the dashboard badge (#753).
- Budget: window kinds, source precedence and per-peer notes (#749).
- The Codex 0.164.0 reviewer is verified with a model-free production receipt (#768).
- CI: `closing-refs` fails a PR that would close an issue its text only mentions (#760).
- The project daemon stops through its normal stop on SIGHUP and SIGQUIT too, so memory sync git (detached since agent-mem 0.7.0) never outlives it (#438, #773).
- The hardcoded operational constants are inventoried and classified (#764). This changes no runtime behaviour.
- The live receipt of hub-settled held deliveries and peer retries is recorded (#434 AC8, #772).

Still open:
- agent-hub backlog #436: serve the hub brief and plan guard from the agent-mem library (agent-mem#40 AC6, hub half).
- The memory sync log fix (#401, PR #748), which waits on the person.
- agent-mem#40 #425 and #426, the agent-mem backlog #433 and #437, and agent-mem#48 AC3 (three green Ubuntu runs on main).

## Known gaps, not blocking

- `docs/operations.md` still says "native memory remains shared according to claude-mem aliases". The code behind it is agent-mem's `projectChain`, and this release didn't change it.
- `memory.worker_url` is still listed as a machine-local key. The config loaders accept it, but it's ignored at runtime.
- Some agent-mem 0.7.0 messages still name `amem` under `ahub memory` (the sync remote hint, and the --all-projects and --to refusals): the library takes no command names there. This is an upstream follow-up.
- The live legs are the person's: a real local or Pi classed prompt (a private turn included), a real Codex command-approval prompt, the `task_planners` refusal on downgrade, and the dashboard Deliverables chip and Code neighbours toggle.
