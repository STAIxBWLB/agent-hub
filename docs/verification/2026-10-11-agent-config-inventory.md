## Decisions

- Exclude `.agents` from scoped automatic file grants: skills may direct code/tool use and are loaded by several supported peers. Existing `.claude`, `.codex`, `.qwen`, `.kimi`, `.kimi-code`, `.pi` and `.mcp.json` exclusions cover their configured project resources.
- Exclude `.claude.json` conservatively as an agent configuration filename. The documented default is home-level `~/.claude.json`, not a project-local file; default project discovery of `.claude.json` was not established. Do not claim that adding this name proves a project loader exists.
- The owner's 2026-10-11 decision keeps `AGENTS.md`, `CLAUDE.md`, `QWEN.md` grantable by default. `scoped_grants.protect_instructions` enables protection for those three names only, including folded and symlink spellings. It persists as machine-local `protect_instruction_files`, applies after the settings write or undo, and is available only through person settings surfaces.
- Configured arbitrary skill/hook paths and configurable context filenames are not a complete name inventory. The hub does not infer additional protected filenames from arbitrary native settings. No guarantee for every vendor-loaded path follows from this list.
- The option affects scoped writes/edits, not instruction reads or explicit human approval/never-ask. A tracked project file cannot set this machine-local policy. Ordinary dashboard sessions may enable protection, but weakening it requires a settings session; agent/tools/conductor surfaces cannot change it.
