# Delivered contract

- `ahub watch kimi|qwen` subscribes to a console-only memory ring, replays it, then streams new items. It sends only `watch` and `status` requests. `q` and Ctrl+C leave without stopping the peer.
- The ring holds at most 500 items and 256 KiB of serialized UTF-8 JSON per peer. Item text is bounded at 4096 UTF-16 code units. Message/thought chunks coalesce up to that cap or a 50 ms flush boundary; tool/permission/end boundaries flush synchronously.
- Tool updates project only declared fields, locations and bounded last text lines, or diff line counts. ACP terminal references without inline output say output is unavailable; filesystem/terminal capability remains disabled. No terminal RPC or native session file is read.
- Private envelopes, daemon-marked private turns and associated PII work show one stub. Privacy stays latched if the task closes during the turn; unreadable privacy state also withholds activity.
- Watch is unavailable for Kimi pull-only TUI mode, off-roster Qwen and non-ACP peers. Jcode is outside this slice. No terminal-provider automation or console Peers-panel shortcut ships here.
- Existing final-answer delivery and existing console approval display retain their own policies. Watch adds no copy to the bus, events, hub.log, UI, tools or claude-mem. A final answer containing a marker can still reach the existing answer bus; that is not a watch side channel.
- Native payload coverage, model/tool execution and TUI claims remain unverified. No performance or quality comparison was measured.
