# Audit: policy decisions made from a realpath-derived name alone (#552, the #541 class)

Date: 2026-10-28. Base: origin/main fa6ef818. Follow-up to #541 (PR #943).

## The class

On macOS APFS, Bun's `realpathSync` (1.4.3, and `.native`) can return another hardlink of the same file: about 1 call in 100 when a file has a second name in a different directory, and never in the 4000 calls where the system `/bin/realpath` was run on the same layout. A decision that tests a name against a name-based policy (the secrets denylist, `.git` and `.agenthub` names, `pii.paths`, `data.readonly`, the shadow ignore policy) after resolving the path with `realPath` can therefore judge a different name than the one the caller used. Both names name the same bytes, so the decision is only wrong when the policy judges the two names differently. It needs a hardlink to a file inside the project to exist first.

## Method

1. `bun ~/.jcode/scratch/inventory.ts` (kept in the PR description, not the repository) listed every `realPath(`, `realpathSync(` and `realpathSync.native(` call in a tracked `src/` file with its enclosing function: 170 call sites in 48 files. Comments, imports and declarations are not call sites.
2. Each call site was read with its source line and, where the line alone did not say what policy follows, the surrounding function. The table has one row per call site. A row is **reachable** when a name-based policy decision is made from the resolved name and the typed name is not also judged.
3. The reverse search covered every caller of `isDenied`, `isHubWritePath`, `isAgentConfigPath`, `matchesPolicy` and `matchesPolicyLexically` for a resolved name reaching it. Two callers that never call `realPath` themselves were reached this way: `screenRegistration` (`src/hub/sources.ts`) and the shadow ignore check inside `Facts.rel`.
4. Reachable callers were measured with the hardlink flip on unmodified main, then fixed, then looped at 5000 iterations (`test/realpath-name-audit.test.ts`, five tests of 1000 each so none needs a timeout above the gate's 20 s).

| Caller | Policy | Calls that decided wrongly |

| `Facts.rel` | secrets denylist | 17 of 3000 |
| `Facts.rel` in a shadow repository | shadow ignore policy (`.agenthub/ignore`) | 17 of 5000 (found in review of this PR) |

| `locate` in `deliverable-files.ts` | secrets denylist | 29 of 3000 |
| `ahub source add` through `screenRegistration` | `pii.paths` | 63 of 4000 |

## Behavior change to know about

`Facts.rel` in a **shadow repository** (a project without `.git`, `ahub init --shadow`) now also asks `git check-ignore` about the typed name. Git answers "beyond a symbolic link" (exit 128) for any name that passes through a symlinked directory, such as `via/f.txt` where `via` is a link to `real`. An answer that is not a plain "not ignored" is never readable fact evidence, so such a path is no longer named by that spelling; the file is still named by its real path (`real/f.txt`). This fails closed and only affects shadow projects, but it is a change for a project that keeps symlinked directories there. `test/realpath-name-audit.test.ts` pins it. Ordinary Git projects do not run this check and are unchanged.

## Plan adjustment

The plan said no new exported API. `screenRegistration`'s input gains an optional `typedPath`, because the only way to judge both names for `pii.paths` is to hand it both; the field is optional and callers without it behave as before. `src/cli/main.ts` and `src/hub/sources.ts` were not in the planned paths and are in this PR for that reason.
