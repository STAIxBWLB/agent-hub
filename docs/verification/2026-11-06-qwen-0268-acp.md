## Native ACP, no prompts

`qwen --acp --bare --advisor off` initialized protocol version 1 with `agentInfo` name `qwen-code`, title `Qwen Code` and version `0.26.8`. Only the synthetic OpenAI terminal auth method was offered. `session/new` succeeded and exposed only `fixture-model`.

The available native mode ids were `plan`, `default`, `auto-edit`, `auto` and `yolo`, initially `default`. Every transition in `default -> auto-edit -> yolo -> default` returned an acknowledgement. This proves the hub's existing three mapped ids as a subset; it adds no mapping for `plan` or `auto`. ACP prompts sent: 0. The leader exited after its owned group received SIGTERM and the producer confirmed `groupGone: true`.

## Actual published permission handler

An exports-only scratch copy of the actual published ACP chunk appended `export{SubAgentTracker,toPermissionOptions,resolvePermissionOutcome}` beside the original, preserving relative imports. The original chunk was not edited. Synthetic client/tool/event ports invoked the native `SubAgentTracker.createApprovalHandler` directly, without a model-generated tool turn.

- The request bound the fixture session, pending tool-call id, raw input, native MCP metadata and permission progress updates.
- The exact options were `proceed_always_project` and `proceed_always_user` as `allow_always`, `proceed_once` as `allow_once`, and `cancel` as `reject_once`.
- Allow-once reached `event.respond` as `proceed_once`; a second actual callback with a cancelled outcome reached it as `cancel`.
- The real outcome helper rejected an unoffered option. No permission-fixture network attempt was recorded.
